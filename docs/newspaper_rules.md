# 一人賛否新聞 生成・組版ルール

> **AI / Automation 向け正本。**
>
> 一人賛否ニュース本文の内容正本は `daily/YYYY/MM/YYYY-MM-DD.md`。
> 新聞の紙面正本は `newspaper/YYYY/MM/YYYY-MM-DD.html`。
> PDFは正本HTMLから生成する配布用成果物とする。

## 1. 正本と責務

- **daily**: ニュース内容・記事1〜10・順番・事実と意見の正本。
- **newspaper HTML**: 見出し階層、列、写真、紙面用要約、紙面高さなど組版の正本。
- **PDF**: HTMLをレンダリングした閲覧・配布用成果物。PDFを直接編集して正本化しない。
- 新聞生成のためにdaily本文を変更しない。
- daily本文から新聞用コピーを作る際は、紙面成立のための要約・圧縮を許可する。ただし、重要事実、論旨、「賛 / ただぁ！ / 結論」の意味とオチを維持する。

## 2. 入力と記事順

- 使用するのは最新の**確定済みdaily**。
- 生成前に記事1〜10、本文、順番を確認する。
- 2面は記事1〜5、3面は記事6〜10を元の順番で掲載する。
- 1面は重要度に応じてトップ、準トップ、小記事へ再配置してよい。

## 3. 紙面構成

### 1面
- 3列構成を基本とする。
- トップ、準トップ、小記事で見出しサイズと占有面積に明確な差を付ける。
- 写真も大・中・小の差を付ける。
- 視覚正本の新聞らしい矩形構成を優先し、カードUI化しない。

### 2面
- 記事1〜5。
- 2列構成。

### 3面
- 記事6〜10。
- 2列構成。

## 4. 文字

- 本文は**12pt基準**。
- 「賛」「ただぁ！」「結論」も十分に読める大きさを維持する。
- 写真注釈、出典、カテゴリなど意味のある補助文字は原則**10pt未満にしない**。
- 紙面へ収めるために文字を小さくしない。
- iPhoneで拡大して無理なく読めることを基準とする。

## 5. 紙面用の文章量調整

- 「何が起きたか / 賛 / ただぁ！ / 結論」はdailyを素材とする。
- 新聞では**文章量を適度に要約・圧縮してよい**。
- 重要記事は長め、小記事は短めでよい。
- 要約はレイアウトの帳尻合わせだけを目的にせず、記事として自然な単位で行う。
- 文章の途中切り、重要事実の脱落、「ただぁ！」や「結論」の消失は禁止。
- 継続ニュースの「今回の差分」は、意味がある場合は新聞でも維持する。

## 6. 写真

- **画像生成は禁止**。
- 写真枚数を「1ページ1枚」などに固定しない。**記事ごとに写真適性を判定**する。
- 使用候補は、公式画像、一次情報、行政・企業・研究機関・競技団体等の公開素材、信頼できる報道写真。
- 適切な写真がなければ写真なしでよい。無関係な代替写真を入れない。
- 当日の写真でない場合は**「資料写真」**と明記する。
- 1面で使用した写真は、2・3面の同じ記事で原則再掲載しない。
- 重要度に応じて `large / medium / small` を使い分ける。
- 写真には出典または出典リンクを付ける。
- HTML正本では、写真URL・出典URL・資料写真判定を追跡できる形にする。

## 7. 写真込み組版

文章だけを完成させてから写真を後付けしない。

各記事を以下の1ブロックとして扱う。

`見出し + 写真 + 何が起きたか + 賛 + ただぁ！ + 結論 + 出典`

写真の有無、縦横比、表示サイズを決めた後で実レンダリングし、記事ブロックの実際の高さを確認して文章量を調整する。

## 8. 下端・空欄・ページ高さの最終調整

ここを**PDF化直前の必須工程**とする。

1. 写真配置を確定する。
2. HTMLを実際にレンダリングする。
3. 1面は3列、2・3面は左右2列の最終記事終端を確認する。
4. 下端差が大きい場合、空白スペーサーではなく**記事の文章量**を増減して整える。
5. 重要記事の情報を戻す、短い記事を少し展開する、長い記事を自然に圧縮する、の順で調整する。
6. 文字サイズを縮小して合わせない。
7. 列終端が自然になった後で、**内容に合わせてページ自体の縦寸法を決定**する。
8. ページ下部に大きな未使用空間を残さない。ページの高さは面ごとに異なってよい。

目安:
- 2・3面の左右列は、目視で段差が気にならない範囲（概ね列高差5%以内）を目標にする。
- 1面は重要度による非対称を許容するが、1列だけ大きく余る状態は避ける。
- 完全な1px一致は目的にしない。新聞として自然な密度を優先する。

## 9. デザイン

- 背景はほぼ白の淡い紙色。
- 角丸、影、グラデーションは使わない。
- 英語装飾は最小限。
- 新聞らしさは、罫線、余白、列、見出し階層、写真サイズ差、紙面密度で出す。
- 視覚正本の構造を保ち、勝手にモダンなWebカードへ再設計しない。

## 10. HTML正本

日付ごとの正本は次に保存する。

`newspaper/YYYY/MM/YYYY-MM-DD.html`

HTMLは以下を追跡できる形にする。

- 内容正本daily
- edition date
- 記事順
- 紙面用コピー
- 写真URL
- 写真出典
- 資料写真判定
- 写真サイズ
- ページごとの列構成
- 最終ページ高さ

将来的にデータとテンプレートを分離する場合も、完成紙面HTMLを日付ごとの組版正本として残す。

## 11. 最終QA

PDF完成前にHTML全3面を実レンダリングして確認する。

- 3面すべて存在する
- 記事順が正しい
- 文字・写真・罫線が重ならない
- ページ外へのはみ出しがない
- 文の途中切れがない
- 本文12pt基準が守られている
- 補助文字が小さすぎない
- 写真の出典・資料写真表記が適切
- 1面写真の不必要な再掲がない
- 左右・3列の下端が不自然にガタガタしていない
- 下部に不必要な大空白がない
- iPhoneで拡大して読みやすい

問題があれば文章量・写真サイズ・ページ高さを調整し、再レンダリングする。
QA通過後だけPDFを完成扱いとする。
