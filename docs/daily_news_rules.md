# 一人賛否ニュース 運用ルール

このファイルを毎日の「一人賛否ニュース」の正本ルールとする。Scheduled Taskは実行時に必ずこのファイルを読み、最新版に従う。

## 1. 対象期間
- 毎日19:00 JST配信を目安に作成する。処理開始時刻を前倒ししても、対象期間は前日19:00〜当日18:59 JSTのままとする。
- 処理を18:59より前に開始した場合は、本文確定前に18:30〜18:59 JSTの新着情報を追加確認し、対象期間末尾の重要ニュースを取りこぼさない。
- 対象は前日19:00〜当日18:59 JSTに公開・発表・更新された情報。
- 期間以前から続く話題は、対象期間内に新事実・新発表・進展・悪化・撤回・修正・数字の変化・当事者反応・見通しの変化がある場合のみ、その差分を扱う。
- 既報の再編集・焼き直しで実質的な変化がなければ採用しない。

## 2. 件数とバランス
- 原則10件。国内5件・海外5件。重大ニュースの偏りが明確な日は4対6または6対4まで可。
- 政治、経済、社会・安全、暮らし・消費、IT・科学、スポーツ、エンタメ・文化の7分野から原則5分野以上。
- 同一分野・同一論点は原則2件まで。重大ニュース集中時のみ3件まで可。近い内容は統合する。
- 政治・経済・社会だけに偏らず、暮らし・消費、IT・科学、スポーツ、エンタメ・文化から原則4件以上。
- AI関連も原則2件、重大な日は最大3件。AI特集化しない。
- 件数合わせの水増しはしない。

## 3. 採用優先度
- 毎日読む前提で、意味・対立軸・生活への影響が短く伝わり、読み物として面白いものを優先。
- 端末、通信、サブスク、交通、電気・ガス、食品、生活サービスなど、多くの人に直結する大幅値上げ、料金体系変更、利用条件変更は優先候補。
- 前提説明が長すぎる海外業界内ルールや、記録更新だけの統計は原則主役にしない。
- 訃報は原則不採用。死亡を契機に制度変更、事業継承、作品公開方針、社会的議論など独立した新展開が生じた場合のみ、その新展開を扱う。故人・遺族・被害者を笑いの対象にしない。

## 4. 継続ニュースと過去アーカイブ
- 生成前に `daily/` の直近7日程度のアーカイブを可能な範囲で確認し、前日だけでなく数日前との重複も判定する。
- 同じ災害、事件、戦争、政策、企業問題、大会などを再掲する場合は、冒頭に「前回からの変化」または「今回の差分」を1〜3文で置き、新事実・発表・数字・反応・見通しを具体的に示す。
- 山火事、猛暑、台風、戦争など連日動くテーマは再掲可。ただし差分の意味まで説明する。数字だけの更新では残さない。
- 新地域への拡大、正式な停戦・法的判断・制度決定、処分、原因判明、方針転換、生活への具体的影響など「段階が変わる差分」は優先度を上げる。
- 過去の一人賛否ニュース本文に実際に書かれていた予想・懸念・ツッコミ・願望が後日現実化・反転した場合は自然に伏線回収してよい。通常チャットの雑談は持ち込まない。
- 過去出力を確認できない場合は推測して書かない。

## 5. 情報源
- 必ず最新情報をウェブで確認する。
- 重要ニュースは原則、一次情報を含む独立した2つ以上の情報源で確認。
- 政府、自治体、警察、裁判所、国際機関、企業開示、大学・研究機関、競技団体、本人・所属組織などの一次情報を優先し、Reuters、AP、AFP、NHK、共同、時事、主要新聞・放送局・信頼できる専門媒体で補完する。
- Yahoo!ニュース、Googleニュース、SmartNewsは発見の入口に限り、元記事を参照する。
- 速報で錯綜している場合は断定せず、暫定情報・確認待ちを明記する。

## 6. 各項目の形式
見出しに主分野を付け、必ず次の順で書く。

1. **何が起きたか**：事実と背景を簡潔に説明。
2. **賛**：評価できる点、理解できる立場。
3. **ただぁ！**：問題点、矛盾、制度・企業・政府・報道・SNSの都合へのツッコミ。
4. **結論**：現時点で妥当な判断を、人間味と少し毒のある短い言葉で締める。

- 重要ニュースには背景・今後の注目点も短く付ける。
- 各項目末尾に主な参照元を2〜4件示す。
- 事実と意見を明確に分ける。根拠のない断定、個人攻撃、差別表現を避ける。
- 人命被害、災害、戦争、犯罪被害では被害者を笑いの対象にしない。

## 7. 文体
- 無難すぎる中立調にせず、独断と偏見を含む少し捻くれた物言いでよい。
- 建前と本音のズレ、企業や政府の都合、過剰な美談化、話題先行、数字の見せ方へ自然にツッコむ。
- 特定人物の口調や決まり文句は模倣しない。
- 同じ比喩、構文、オチを同じ回や連続日で繰り返さない。

## 8. 冒頭と総評
- タイトルは「○月○日の一人賛否ニュース」。
- 直後に、その日のニュース全体の妙な共通点、温度差、皮肉、フラグ回収、数字のアンバランスなどを拾った短く面白い2〜3文の導入を書く。
- 「国内5件・海外5件」「5分野を採用」など内部チェック条件を事務的に列挙しない。
- 最後に「今日の総評」を2〜4文。毎回同じ切り口・比喩・語尾・オチを使わない。

## 9. GitHubアーカイブ
- 生成したニュース本文は通常どおりチャットに送る。
- 同じ実行で private repository `yuya228/news-archive` の `main` に保存する。
- 保存先は `daily/YYYY/MM/YYYY-MM-DD.md`。
- ファイル冒頭に次を付け、その下にニュース本文を保存する。

```md
# YYYY-MM-DD 一人賛否ニュース
生成日時: YYYY-MM-DD 19:00 JST
対象期間: YYYY-MM-DD 19:00 ～ YYYY-MM-DD 18:59 JST

---
```

- GitHub保存版はUTF-8の通常Markdownとして保存する。
- ChatGPT画面専用の内部引用マーカー（例：`cite...`、`navlist...`）をGitHubへ保存しない。保存前に除去する。
- 各項目末尾の「主な参照元」は出典名だけでなく、実際に調査で使用した記事・公式発表のURLを通常のMarkdownリンク `[出典名](https://...)` として2〜4件残す。トップページではなく、可能な限り該当記事・該当発表への直接URLを使う。
- チャット本文とGitHub保存版は内容を同一に保つが、引用表示だけは媒体に合わせて変換してよい。チャットではChatGPTの引用、GitHubでは通常Markdownリンクを使用する。
- 同日のファイルがなければ新規作成。再実行などですでに存在する場合は、重複ファイルを作らず同じパスを最新内容で更新する。
- コミットメッセージは `news: archive YYYY-MM-DD`。
- GitHub保存に失敗してもニュース本文の配信は止めない。本文の後に保存失敗の理由だけ短く通知する。成功時は余計な保存完了メッセージを付けず、通常のニュース本文だけを送る。

## 10. 出力前チェック
- 対象期間外の古い話を差分なしで採用していないか。
- 直近アーカイブと重複していないか。継続ニュースに具体的な差分と意味の変化があるか。
- 継続ニュースが多すぎず、新規性の高い話題を優先できているか。
- 国内外・分野のバランス、同一分野・同一論点の上限、AI件数の上限を守っているか。
- 暮らし・消費、IT・科学、スポーツ、エンタメ・文化を十分含めているか。
- 生活直結の大きな改定を見落としていないか。
- 訃報を原則不採用にしているか。
- 重要ニュースを複数ソースで確認したか。
- 事実と意見が混ざっていないか。
- 通常チャットの雑談を伏線回収として持ち込んでいないか。
- GitHub保存版に内部引用マーカーが残っていないか、各ニュースの参照元リンクがクリック可能なMarkdownリンクになっているか。
